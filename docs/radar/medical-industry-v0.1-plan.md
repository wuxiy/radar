## 1. 已确认的目标

Radar 面向在中国医疗行业工作的后端工程师，持续发现与卫健委、医院和区域平台项目有关的行业变化。重点覆盖医院影像系统、区域电子处方流转、医疗数据平台、医疗高质量数据集及相关医疗 AI 应用。

用户已确认首批关注 HIT 专家网、CHIMA、健康界、动脉网，再加入项目相关医院官网和采购信息。当前高质量数据集项目是首个重点专题；mark、coder-os 承接深入阅读和技术学习。

每条精选应说明：发生了什么、原文证据是什么、处于什么阶段、与哪类医疗项目有关、值得继续查什么。首页使用现有热点和精选，按主题继续阅读，日报与周报承接持续跟踪。

首版保留 AI 行业包，新增医疗行业包。两个行业复用现有采集、评分、事件归组及发布流程，通过独立进程与逻辑数据库隔离；医疗内容配置集中在行业包；采集适配只有在已确认来源无法通过现有配置验收时，才作为独立工作项处理。

## 2. 首批来源与接入顺序

### 2.1 来源清单

下表仍记录自动化接入提案；当前已登记且暂停的来源 ID 与方式见 [医疗来源说明](../../industry/profiles/medical/sources.md)。四个信息站已由用户确认；医院具体名单和地方采购入口随项目地域补齐。首版规模建议为四个信息站、1–2 家医院、一个医疗采购入口，总计 6–7 个来源；只有验收通过的入口才进入运行清单。

| 批次 | 来源与入口 | 建议 source ID / 分级 | 计划方式 | 内容用途与验收重点 |
| --- | --- | --- | --- | --- |
| A | [HIT 专家网 RSS](https://www.hit180.com/feed/) | `rss-hit180` / T2，`first_party=false` | `rss` | 医疗信息化与数据治理；核对订阅摘要、正文、作者和原始出处 |
| A | [CHIMA](https://www.chima.org.cn/Home) | `web-chima-industry` / T1，`first_party=true` | `web_list`，选定新闻或行业动态栏目 | 医院建设经验、行业调查、数据与区域协同；识别自有发布与转载 |
| B | [健康界信息化频道](https://www.cn-healthcare.com/xinxihua/?type=3) | `web-healthcare-informatics` / T2，`first_party=false` | 核实栏目列表，再决定 `web_list` / 公开 JSON / `external` | 信息化和相关医院管理实践；必须保留发布作者，排除导航、热榜与普通科普 |
| B | [动脉网](https://www.vbdata.cn/new) | `web-vbdata-industry` / T2，`first_party=false` | 优先限定主题或栏目，再验证 `web_list` / 公开 JSON | 医疗数据产品、影像 AI、合作与市场变化；筛除无关药品融资和泛产业消息 |
| C | 项目相关医院官网 | 选定医院后固定 ID / T1，`first_party=true` | `web_list`；缺稳定列表时先 `external` | 选 1–2 家有实质公开材料的医院，关注信息中心、科研、数据平台及建设发布 |
| C | [中国政府采购网](https://www.ccgp.gov.cn/)与项目所在省级平台 | 按实际发布平台固定 ID；全国入口建议 `external-ccgp-medical` / T1，`first_party=true` | 首版从筛选过的公告做 `external`；稳定搜索或栏目验证后再自动化 | 采购意向、需求、结果、更正、合同等阶段；匹配采购单位、项目编号和交付范围 |

T1 是来源身份与精选门槛的配置，材料仍需独立评价。CHIMA 转载某厂商的效果描述不能自动成为独立验证；采购公告可证明采购动作，不能证明建成或有效。健康界的机构投稿也不能因为发布在平台上就整体升级为一手来源。

同一平台的官网、RSS和公众号先选择一个主要入口，避免重复处理。确有独有材料时再补第二渠道，并核对是否重复及对热度的影响。

| 入口 | 本次观察 | 下一步必须补齐 |
| --- | --- | --- |
| HIT RSS | HTTP 200，XML 可解析，10 条订阅条目，最新条目日期为 2026-09-29 | 用项目 RSS 采集器核对至少 3 条，检查正文补齐与版权设置 |
| CHIMA `/Home` | 原始 HTTP 200，可见文章路径及 2026 年 9 月日期；浏览工具一次超时 | 选定当前更新的栏目，验证条目与日期对应；旧 `/Html/Index.html` 页面含较多历史区块，不能直接当作最新列表 |

医院具体名单待用户提供。已经查到的同济医院发布和四川省骨科医院采购仅用于方案样例，不自动视为用户项目相关医院。

### 2.3 接入原则

1. 先选来源范围，再验证列表、详情与日期，最后创建信源。普通 HTML 模式不执行 JavaScript，CSS 选择器不能生成尚未返回的条目。
2. `rss`、`web_list`、`json_list` 可预览；配置只使用 [config-keys.ts](../../packages/backend/src/sources/config-keys.ts) 支持的字段。`web_list` 顶层没有 `summarySelector`，详情补齐放在 `detail` 中。
3. 采购关键词先用于检索和人工选择；现有 `ingestNoiseFilter.keepIfMatches` 只是噪声排除的例外，不是正向关键词白名单。首版不对全国采购主页做全量采集。
4. RSS、官网和公开接口优先。需要公众号时再核实真实账号 ID、Dajiala 凭据与额度；需要 Jina 时显式配置并经过预算与回执。未具备条件的来源保持暂停。
5. 频率初始建议为 60 分钟，并观察现有自动调频结果。外部补录先按工作日检查；当前调频会改变 RSS/网页/JSON 的间隔，不能承诺所有入口长期按手工设置运行。

具体作者、账号和节目由用户提供，本阶段不代选名单。预留以下登记信息：

| 渠道 | 用户提供的信息 | 后续核验与接入 |
| --- | --- | --- |

| key | 类别 | 纳入内容 |
| --- | --- | --- |
| `medical-it` | 医疗信息化 | PACS/RIS、影像云、电子处方、区域平台、结果互认、医院业务协同 |
| `medical-data` | 医疗数据平台 | 数据治理、互联互通、主数据、专病库、科研数据平台、可信数据空间 |

保留现有 `company` / `field` / `genre` 结构，显示名可改为“机构与企业 / 方向 / 资料类型”。资料类型可用标签表达医院实践、采购信息、政策标准、产品发布、研究评价和行业解读；继续沿用七个 `ITEM_TYPES` 和五维评分结构。

## 4. 精选与写作规则提案

### 4.1 什么值得看

| 优先保留 | 重要的原因 |
| --- | --- |
| 与医院或区域系统边界有关的新政策、标准和规则 | 可能改变接口、流程、评价或交付要求；不要求提到 AI |
| 交代数据场景、生产过程、质量方法和局限的建设实践 | 帮助判断哪些工作应进入实际项目 |
| 医院披露的需求、建设结果和问题 | 能连接信息部门、临床与管理的真实诉求 |
| 数据产品的交付、使用、验证或运营变化 | 能解释从项目建设到持续使用的过程 |
| 有代表性的采购需求或交付要求变化 | 帮助理解预算购买的能力和市场需求 |
| 揭示医疗 AI 或数据方案限制的研究、实践或分析 | 帮助确定可用范围与失败条件 |

降低优先级：只有“赋能”“海量高质量数据”的宣传、同一材料的重复转载、普通会议报名、没有项目关联的融资和药品新闻、纯健康科普及通用技术版本更新。会议若发布了实质建设成果，按成果评价。

初始门槛保持 T1=60、T1_5=65、T2=76、`understandFloor`=50，等用户标注样本后校准，不能以提高资讯数量为理由随意调低。

### 4.2 摘要要回答的问题

使用现有 `titleZh`、`summaryZh`、`editorialJudgment`、`tags` 等输出字段，在文字中说明：

- 发生了什么，涉及谁、什么场景和时间。
- 原文披露了哪些证据；没有披露哪些关键条件。
- 是计划、试点、采购、部署、验收还是研究结果，避免把宣布当成完成。
- 对医疗工程师有什么参考价值；推断明确标记为推断。
- 应回到哪份公告、医院发布、产品材料或附件查证。

数据集材料重点读病种、任务、模态、来源、标注、质控、验证和使用条件；原文没有就记为“未披露”。采购材料重点读采购单位、项目名称/编号、阶段和交付内容；预算不能冒充成交金额，成交不能冒充验收。预算、截止日期与交付要求属于不同时间和事实维度。

同一项目的公告、更正、结果和合同可作为后续进展；相同病种或“数据集”标签不能作为同一事件的充分依据。媒体复制同一医院或企业材料不等于多份独立效果验证。现有热度算法不因本计划而改变。

数据库处理：新测试库核对 seed 结果；已有库先导出来源与主题清单，审核旧来源启停和旧主题。`scripts/seed.ts` 对已有 source ID 不覆盖，主题 seed 也不会自动删除旧主题；不能把编辑 JSON 当作数据库迁移完成。保持历史内容，必要的数据库迁移按编号追加并向后兼容。

公开页面、RSS、API、MCP继续共用 `packages/backend/src/publication/`。读者访问不触发模型；`site_fulltext` 与 `syndicate_fulltext` 默认关闭，公开展示摘要和原文链接。Radar 采集公开行业资料及数据集说明，患者级数据处理属于实际医疗项目。

### 6.1 需要单独验收的来源缺口

- **动态列表**：健康界等入口可能只有页面框架和热榜；先核实公开接口或稳定栏目。仍不具备条件时暂停自动接入，用人工选择后的外部推送补充。
- **采购与规范附件**：当前正文提取直接处理 HTML，没有原生 PDF 页码/章节引用管理。首版保留附件链接并人工核查；只读到公告正文时明确不包含附件分析。
- **外部推送**：现有 `/api/ingest/items` 接收标题、URL、日期、作者和 `raw`，不直接接收抽取正文。它解决发现与入库，正文仍走现有提取流程。自动创建的来源默认 `isolated`，需检查身份分级与参与方式后才能公开；暂停来源返回 409，不能持续盲重试。
- **付费备用渠道**：公众号、Jina与模型请求需要对应凭据、预算和回执；生产小批验证与离线测试分别安排，不绕过熔断。

确需新增适配时，交付一个具体来源的适配、离线样本和失败行为验证。完整 PDF 管线、全文推送契约、独立多领域评分和站内知识问答不作为首版前置条件。

## 7. 分阶段实施与验收

以下用时是工作量估计，受来源稳定性、名单补齐和人工标注影响。约 5–8 个工作日形成首轮可验收版本，另观察两周；以每阶段验收证据推进。

| 阶段与依赖 | 交付 | 可关闭的验收条件 |
| --- | --- | --- |
| **P0：冻结实施规格**，约半天 | 四站来源登记、确认后的分类与编辑例子、模型和采集预算；登记地域/医院待定项 | 四站使用本次已确认名单；每源有 URL、身份、方式、状态与负责人；医院和地方采购具体入口可留待 C 批，未核验的入口保持暂停 |
| **P1：最小行业包**，依赖 P0，约 1–2 天 | 文案、分类、主题、模块开关与提示词；更新相关测试样例 | 类型/构建/相关离线检查通过；医疗材料无需 AI 关键词；输出符合词表与既有契约；通用宣传案例不被改写成已验证能力 |
| **P2：分批接入**，依赖 P1，约 2–3 天 | A 批 HIT/CHIMA → B 批健康界/动脉网 → C 批医院/采购；每源留验收记录 | 每源至少 3 条人工核对真实材料，检查标题、链接、日期、作者、正文范围；重复重放不新建同一材料；历史回填、暂停、失败行为符合现有规则。未通过者明确降级或暂停 |
| **P3：专题与精选校准**，依赖 P2 已验收来源，约 1–2 天加用户标注时间 | 高质量数据集主题与参考清单；先审 20–30 条，再准备 100–200 条 gold | 五个专题问题各有有效材料或明确缺口；开发/留出集按事件拆分，重复转载不跨集合；记录误选、漏选、提示词/模型/门槛与费用，再决定阈值 |
| **P4：有限试运行**，依赖 P3 与运营条件，约两周 | 经确认预算的来源与模型运行；精选、日报、周报及后台运行记录 | 新资料经采集→处理→公开可追踪；重要主题有覆盖；摘要及公开出口一致；有材料时正常成刊；来源失败与付费预算可见 |
| **P5：复盘与下一版**，依赖 P4 | 保留/暂停来源清单、错例总结和明确的小范围改进项 | 用户能指出获得的项目新认知；根据证据决定补医院、改预筛或做具体适配；专题简报需求另立项 |

P2 各批独立验收，B/C 批的入口或名单待补不阻止 A 批推进。P3 使用已验收来源及人工核查的背景材料开始准备样本。

P2 中的真实材料通过独立安排的公开来源核查或运行验收取得；自动化测试使用脱敏、最小化的离线材料，不访问外部网站。来源样本记录保存在 `.data/` 等不提交目录，仓库只提交必要的最小测试夹具、规则和验收说明。

### 7.1 校准与试运行建议指标

下列是初始验收提案，待用户确认阅读偏好后冻结；不是当前测量结果，也不直接改变评分数字。

- 留出集建议先争取查准率 ≥80%、查全率 ≥80%，同时看各主题错例与样本数量；少量样本的高比例不能证明整体效果。
- 每源抽查至少 3 条的标题、链接与原文日期全部正确，正文无导航/其他文章混入；来源不具备三条有效材料时继续观察。
- 首批重放样本中同 URL 不重复入库；同一事件的多篇报道保留出处并归组，不能把不同采购项目误合并。
- 页面、RSS、API、MCP对同一条资料的事实、分类、撤回与全文范围一致。
- 精选数量按价值与供给决定，不设置每日凑数指标。医院与采购信息低频，不因为日更少就自动判为无价值。
- 记录采集失败、日期/正文缺失、处理失败、费用及人工认定的误选/漏选，保留暂停单个来源和关闭自动采集/模型的操作路径。

评测沿用 [SelectBench](../selection.md)。这里的 gold 标注判断行业资讯是否值得阅读，与实际医疗项目的数据标注和数据集质量验收是两套工作。

## 8. 检查与上线条件

实施时按 [AGENTS.md](../../AGENTS.md) 执行类型检查、网页构建、前后端测试、临时 `_test` / `_ci` 空库迁移和站点 smoke。离线用例重点验证：无 AI 关键词的有效材料、纯营销、日期缺失、历史回填、重复转载、不同采购阶段、附件未读及正文失败。

开发与测试保持 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED`、`FEISHU_*_ENABLED`、`INDEXNOW_SUBMIT_ENABLED` 关闭。此前完整后端测试中的模型路径仍有本地模拟测试例外待处理；未解决部分必须记录为未验收，不把静态检查或既有测试结果当作本轮全链路证明。

运行试验单独确认模型与备用采集服务、预算、运行环境和启用范围，按批次启用来源。公开发布前核对站名/MCP 前缀/`SITE_URL`、品牌、条款及隐私内容；凭据只在后端配置，`.env`、密钥和 `.data/` 不提交。
